一、核心功能验证（权重 40%）
个人信息机制及基础发车拼车功能
【是 / 否】用户注册/登录流程完整，且能选择/编辑个人信息标签
【是 / 否】发起人可成功创建“拼车”，设置剧本、时间、锁车截止时间
【是 / 否】玩家能在“组局大厅”看到待加入的车队，并能查看车内已有玩家的信息（标签、信用分）
【是 / 否】玩家申请上车后，系统能成功将其加入车队，且所有的车内已有玩家可以收到通知
【是 / 否】满足“满员”或“截止时间”条件时，系统能正确执行“锁车”或“自动解散”操作，且所有玩家收到通知
【是 / 否】剧本大厅能正常展示剧本列表、类型、简介等信息
信用机制
【是 / 否】信用分信息能正常展示，并对“跳车”行为有明确的扣分警示窗口和扣分规则说明
【是 / 否】玩家能看到自己的信用分流水
评价机制
【是 / 否】玩家在完成剧本杀后，系统能自动识别出“同车玩家”并开放相应的评价入口
【是 / 否】玩家无法对未同车的用户进行评价，且同一局内不可重复评价同一玩家
【是 / 否】评价完成后，系统有明确提示“评价完成”，系统能记录评价结果并更新被评价玩家的信息（在他人评价页面）
二、用户价值验证（权重 25%）
【是 / 否】用户能独立完成从“找车”到“上车”的完整操作
【是 / 否】“标签”、“信用分”和“评价”机制能对用户拼车产生帮助（问卷和用户试用反馈）
【是 / 否】获得至少 10 个目标用户（剧本杀玩家）的真实使用反馈和改进意见
三、商业模式验证（权重 15%）
【是 / 否】有初步的定价策略设想
【是 / 否】展示了未来可能的获客路径
四、技术/数据验证（权重 20%）
【是 / 否】小程序可正常访问，无严重崩溃或白屏
【是 / 否】后台能记录关键数据：发起局数、成功拼车局数、用户跳车次数、用户注册数
【是 / 否】代码结构清晰，后续可扩展（如增加支付押金等功能）
